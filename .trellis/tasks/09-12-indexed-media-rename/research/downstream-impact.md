### Concrete cutover obligations, deferred to their owners

1. **Keep artifact filename, loader/install name and registered type distinct.** The host test copies an input artifact to `plugin.so` at `D:/Repositories/rulego-server-docker/scripts/verify-plugin-runtime.sh:28`, mounts `/app/data/plugins` at line 33, and asserts the already-namespaced type `myPlugins/upper` at line 49. This shows that the file's spelling alone is not a component-registry acceptance check. It does **not** establish the loader's namespace behavior for an unprefixed `indexedMedia` type. The main session's source-side design must determine the intended installed basename and exact registered type; the deployment owner must verify both by readback. Do not infer that merely renaming an old binary changes its registration.
2. **Inventory and cut over deployed rules together with the plugin.** The deployment/rule-chain owner must find all stored rule and node-pool `.type` values, generated/exported rule copies, editor templates and registry checks that actually use the old type. Replace the old type with the approved new type for the breaking release. Node instance IDs and `ref://` owner references are separate graph identities: retain them unless explicitly selected for renaming; if an ID changes, update every dependent reference consistently. No local downstream rule JSON using `indexedVod` was found; that does not clear remotely stored rules.
3. **Inventory installation automation and remove unintended old-plugin loading during the approved cutover.** The deployment/release owners must reconcile the new repository download URL, asset basename, version/platform selection, checksum and ABI-sidecar filenames, copy destinations, mounts, restart procedure and rollback artifact/rule set. Do not rely on a hosting-provider redirect, keep a second old-name binary loaded as implicit compatibility, or silently delete persistent media/catalog data. Existing scripts outside these four local siblings and installed files were not inspected. All replacement/removal/restart actions remain unexecuted and need their normal authorization.
4. **Verify the release in its real host composition.** Keep the ABI/sidecar checks documented at `D:/Repositories/rulego-server-docker/README.md:73` and use the matching runtime. Verify the expected new registry entry, successful migrated rule loading, preserved shared-node references, coexistence with `resourceOrigin`/`ffmpegOverIp`, a bounded producer invocation and the relevant video playback path. The host probe's registry check at `D:/Repositories/rulego-server-docker/scripts/verify-plugin-runtime.sh:49` is not producer, seek or playback proof. New audio-only support and deployment of the independent audio plan are outside this rename.
